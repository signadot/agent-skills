Look at the cluster yourself

The trial keeps the cluster's credentials in its own kubeconfig, inside the trial folder, so your current kube context is unchanged and tools like kubectx don't list the trial's cluster. Point a terminal at it:

Use the trial's cluster in this terminal (kubectl, kubectx, k9s and Lens all follow this variable):

export KUBECONFIG="TRIAL_FOLDER/kubeconfig"
kubectl config current-context

The demo app, with each sandbox's pod next to the normal ones:

kubectl -n hotrod get pods

Signadot's operator, which routes requests to sandboxes:

kubectl -n signadot get pods

The sandboxes and their links, with the trial's Signadot CLI:

TRIAL_FOLDER/bin/sd sandbox list

To add the cluster to your own kubeconfig instead, run kind export kubeconfig --name signadot-trial; note that it also switches your current context to kind-signadot-trial. Sandboxes, route groups and test runs are also in the Signadot dashboard: app.signadot.com.

Everything keeps running until you ask your agent to remove it.
